# 充电保护器 · 演示操作手册（v3 · 开机即模拟演示 · 按键手动触发）

> 配套固件：`Objects\project_1.hex`（2026-10-11 v3，0 Error，`code=4966 / data=120`）
> **程序开机直接进入"模拟演示模式"**：电流/温度全部由程序内部数据提供，
> **不依赖 INA219、不依赖温度传感器**——继电器、板载 LED、计时、点阵全部照常工作。
> 演示靠按键触发：**K1 = 过流跳闸、K2 = 充满断电、长按 K1/K2 = 升/降温、K4 = 复位**。

---

## ★ 先回答你最关心的：继电器为什么没变化 / LCD 为什么一直亮

上电后 0~1.5 秒会听到继电器自检的**两下"咔哒"**（吸合-断开-吸合-断开）。对表判断：

| 上电自检的表现 | 结论 | 怎么办 |
|---|---|---|
| **听得到"咔哒"，继电器模块上的小红灯跟着亮灭** | 程序和继电器控制都正常 | 按 K1 做跳闸演示即可 |
| **没有任何"咔哒"，模块红灯也不亮** | 模块没供电：查模块 VCC/GND 两根线 | 接好即可 |
| **没有任何"咔哒"，但模块红灯常亮** | 控制信号没进来：查 IN 线是否真的插在**开发板 P1.0** | 接好即可（注：低电平吸合，IN 悬空/接高都不吸） |
| **有"咔哒"，但跳闸时 LCD 不灭** | LCD 的电没走继电器触点 | 检查负载链路：`5V → 继电器 COM → NO → INA219 VIN+ → VIN− → LCD VDD → GND`（LCD 的正极必须从继电器 NO 过去，不能直接接 5V） |

想单独验证继电器模块本身：拿一根杜邦线把 IN 直接接 GND，应立刻吸合（你之前记录过这个现象）。
这是**纯硬件判断**，跟代码无关——代码这边继电器每个控制周期都在真实开合。

## 0. 展示思路（一句话讲清）

> "这是一款充电保护器：INA219 实时监测充电回路的电压电流，电流超限 → 1 秒内继电器跳闸断电
> （自锁，必须手动复位，像空气开关）；电流衰减到阈值以下持续 5 秒 → 判定充满 → 自动断电；
> DS18B20 温度超限也会立即断电。
> 因为实际硬件不稳定（温度传感器引脚松、负载回路接触不良），
> 我把程序做成了**开机即模拟演示**：用内部数据驱动全部保护逻辑，
> **逻辑和后端执行（继电器、LED、计时）全都是真的，只有传感器读数用模拟值代替**，
> 状态文字前面带 `*` 号标明是模拟数据，绝不含糊。
> 硬件修好后改一个宏就能切回真实测量。"

## 1. 接线（照照片原样就行，一根线都不用动）

```
开发板 5V  ──▶  继电器 COM
继电器 NO  ──▶  INA219 VIN+
INA219 VIN- ──▶  负载正极（LCD1602 的 VDD）
负载负极   ──▶  开发板 GND
INA219: VCC→5V  GND→GND  SDA→P1.2  SCL→P1.3  (A0/A1 悬空 = 地址 0x40)
```

**负载就用你的 LCD1602**（只接 VDD/VSS 两根电源线当耗电负载，数据线不接）：
- 它既是负载又是"电源指示灯"：**亮 = 正在供电，灭 = 保护跳闸**，跳闸瞬间非常直观；
- 屏幕显示交给**板载 8×8 点阵**（走 P0 自动识别，不会和 LCD 冲突）。

> 就算这条回路完全没接好，v3 的程序照样能演出完整现象（因为用的是模拟电流），
> 只是"LCD 熄灭"这个效果需要回路通着才看得到。

### 板载 LED 柱状条（不用任何外接元件）

江协板/普中板自带的 **8 个 LED 全在 P2.0~P2.7（共阳接法，低电平点亮）**，直接拿来做显示：

| 状态 | 8 个 LED 的表现 |
|---|---|
| 空闲 IDLE | 全灭 |
| 充电中 CHRG | **按电流大小亮 1~8 格**（以过流阈值为满格）→ 电流柱状图 |
| 已充满 FULL | 8 格全亮 |
| 过流跳闸 / 过温 | **整排"全灭 ↔ 全亮"交替闪烁**（告警） |
| 开机 | 1 格 → 8 格流水灯，再全亮一下（验灯） |

**三个要知道的共用关系**（都在 P2 口，属正常现象）：

1. **P2.5 在很多板子上接了蜂鸣器**：灯亮到第 6~8 格时可能听到响声，不想听就拔掉蜂鸣器跳线帽；
2. **P2.2/2.3/2.4 同时是数码管位选**：亮这几格时数码管可能有一点窜光，不用管；
3. **P2.5/2.6/2.7 同时是 LCD 控制线**：所以用 LED 柱状条时**不能再把 LCD1602 当显示器**
   （你现在正好是把 LCD 当负载用，不冲突）。想两者共存就把 `LED.h` 里 `LED_BAR_N` 从 8 改成 5。

> 其余空闲引脚：`P1.1`、`P1.4`、`P1.5`、`P1.6`、`P1.7`、`P3.7`（DS18B20 停用后空出）。

## 3. 上电后是这样（不用屏幕也能看懂）

| 时间 | 现象 | 说明 |
|---|---|---|
| 0~1.5s | 继电器"咔哒"两下 + LED 跑一次流水灯再全亮一下 | 继电器与灯路自检 |
| ~2s | **LED 亮 4 格，停一下** | 已进入**模拟演示模式**（正常，不用管 INA219 在不在线） |
| ~2.4s | LCD（当显示器时）出 `CHARGE PROTECTOR` | 屏和对比度正常 |
| ~5s | 自检页 `MODE:SIM DEMO / INA:xx RLY:ON` | `SIM DEMO` = 正在用模拟数据演示 |
| ~6s | 实时页 `U:5.00V I:  50mA / *CHRG 00:00:00`，**LED 亮 4 格、计时开始走** | 模拟"正常充电中"，等按键触发 |
| 之后 | 程序停在这个状态等你按键（K1/K2/K4，见第 4 节） | **不会自己动作** |

**点阵图标含义**

| 图标 | 含义 |
|---|---|
| √ 常亮 | 一切正常 |
| ! 闪烁 | 真实测量模式下 INA219 有问题（模拟模式下不会出现） |
| × 闪烁 | 正在保护：过流跳闸 / 过温（配合 LED 整排闪） |

**默认阈值（模拟电流就是照着它设计的）**

| 参数 | 默认值 | 含义 |
|---|---|---|
| FULL 充满判定 | **20mA** | 电流低于它并持续 5 秒 → 判满断电 |
| OVER 过流保护 | **100mA** | 电流超过它并持续 1 秒 → 跳闸（自锁） |

模拟电流三档正好卡在两个阈值两侧：

| 模拟电流 | 效果 |
|---|---|
| **50mA**（默认） | 正常充电中：柱子 4 格、继电器吸合、计时走 |
| **10mA** | 低于 FULL → 5 秒后判"充满"自动断电、LED 全亮 |
| **300mA** | 高于 OVER → 1 秒后"过流"跳闸、LED 整排闪、自锁 |

## 4. 演示动作（一个键就是一个演示，照按就有现象）

### 主秀：过流保护跳闸（核心成果）

1. 上电后看到 `*CHRG`、计时在走、LED 亮 4 格 —— 这就是"正在充电"
2. **按一下 K1**（短按）→ 模拟电流变成 300mA
3. **看 LED：柱子立刻涨满 8 格**
4. **1 秒后**：继电器"咔哒"跳闸，LCD 负载**当场熄灭**，**8 个 LED 整排交替闪烁**，
   点阵整屏闪 ×，状态变 `*OC!!`
5. **按一下 K4**：复位解除，继电器重新吸合，LCD 重新亮起，LED 回到 4 格，计时从 0 重新走

讲解点：*"跳闸是自锁的，必须人为复位——就像家里的空气开关，防止故障没排除就自动恢复供电。"*

### 第二秀：充满自动断电

1. 上电后在"充电中"状态（`*CHRG`、计时在走）
2. **按一下 K2**（短按）→ 模拟电流变成 10mA（充到末期电流衰减）
3. **等 5 秒**：状态变 `*FULL`，继电器"咔哒"断开，**8 个 LED 全亮**，计时停在断电那一刻
4. **长按 K3** 回到 50mA 正常充电（或按 K4 复位）

讲解点：*"真实充电末期电流衰减到几十 mA，用'电流小于阈值并持续 5 秒'来判满，
而不是等电流等于 0——永远不会正好等于 0。而且必须真的见到过充电电流才允许判满，防止误判。"*

### 第三秀：过温保护（温度保护逻辑，传感器坏了也能演）

1. **长按 K1**（≥1 秒）→ 模拟温度 +5℃，连按三次到 45℃ 以上
2. → 状态变 `*HOT!`，继电器立刻断开、LED 整排闪 —— 过温保护
3. **长按 K2** 降温 → 温度降回 (45−2)℃ 以下自动恢复充电（回差设计，防止临界抖动）

讲解点：*"温度传感器硬件坏了，但保护逻辑一行没删，用模拟温度完整跑通了；
换一个新的 DS18B20，把代码里 TEMP_SENSOR_EN 改成 1 就能用真实温度跑。"*

### 顺手展示：按键反馈条

按住任意键，板载 LED 亮对应格数：**K1 亮 1 格、K2 亮 2 格、K3 亮 3 格、K4 亮 4 格**；
按住超过 1 秒，对应格数开始闪（表示长按被识别）。

用途：**证明四个按键全部生效**，另外还能核对板上丝印和引脚顺序。

## 8. 看不到现象时的排查顺序

**第 0 步永远先做**：按住 K1，看 LED 是不是亮 **1 格**。
- 亮 1 格 → 新固件已经在板子里，往下查；
- 亮 2/3/4 格 → 固件是新的但按键映射要改（见第 6 节）；
- 完全没反应 → **固件根本没烧进去 / 没冷启动**，重烧。

1. **上电前 1.5 秒听不到继电器自检的"咔哒"** → 继电器根本没被驱动，是**接线/供电问题，不是程序**：
   - 继电器模块上的电源红灯**不亮** → 模块 VCC/GND 没接好；
   - 红灯亮但不吸合 → IN 线没插在**开发板 P1.0**（低电平吸合，IN 悬空/接高不吸）；
   - 想验证模块本身好不好：拿一根杜邦线把 IN 直接接 GND，应立刻吸合（你之前记录过这个现象）。
   - 若继电器本身正常但和板子接不通，程序其余现象（LED 柱状条、计时、点阵、按键反馈）**照样能演**，
     跳闸这一下就只剩"LED 整排闪 + 状态 OC!!"，讲解时说清"断电动作由继电器执行"即可。
2. **有"咔哒"，但按 K1 跳闸时 LCD 不灭** → LCD 的电没经过继电器触点：
   负载链路必须是 `5V → 继电器 COM → NO → INA219 VIN+ → VIN− → LCD VDD → GND`，
   LCD 正极**不能直接接 5V**。跳闸断的是这条链，不是板子上的 5V 电源轨。
3. **LED 完全不亮** → 查 P2 口供电、5V；LED 自检流水灯都没跑说明主程序没跑起来 → 查晶振（`Timer0.c` 顶部）、P0 上拉。
4. **LED 一直全灭、按住按键也没反应** → 晶振/供电问题，同第 3 条。
5. **LCD（当显示器时）背光亮没字/黑方块** → 拧对比度电位器 V0。
6. **LCD 完全不通** → 程序自动切点阵（点阵亮 √ 就说明程序在跑）。
7. **"充满"断电太快（按 K2 后 5 秒就断）** → 这是设计好的，就是充满判定演示；想延长把 `main.c` 里 `FULL_CONFIRM_SEC` 改大。
8. **按 K1 后没跳闸** → 看 LED 有没有先涨到 8 格；没有的话说明固件是旧的（重烧）。
9. **继电器方向反了**（该吸合时不吸合） → `Relay.c` 里 `RELAY_ACTIVE_LOW` 1 改 0，重编译。
10. **按 K1 却亮 2 格** → 按键丝印与引脚顺序不符，改 `Key.c` 顶部 `KEY_PIN_MAP`（江协板应为 `{1,0,2,3}`）。
11. **想换成"开机用真实测量"** → `main.c` 顶部 `#define SIM_BOOT_DEFAULT` 从 1 改成 0，重新编译。
