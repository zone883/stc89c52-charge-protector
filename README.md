# 充电保护器 (Charge Protector)

基于 51 单片机（STC89C52）的锂电池充电保护装置 —— 深圳大学 CPOE 实验室招新作品。

单片机用 **INA219** 采集充电回路的电流、用 **DS18B20** 采集电池温度：
温度超过设定上限时断开继电器、切断充电回路；充电电流消失时同样断开。
当前状态用一块 **8×8 LED 点阵**显示（√ 表示正常，× 表示保护动作），
温度上限可以在板子上用两个独立按键现场调整。

> 源码已开源：**https://github.com/zone883/stc89c52-charge-protector**

## 一、功能

| 功能 | 实现方式 | 状态 |
| --- | --- | --- |
| 温度采集 | DS18B20 单总线读取，单位 ℃ | 传感器引脚松动，见第六节 |
| 电流采集 | INA219 读分流电压寄存器，单位 mA | 端子自焊焊点不良，见第六节 |
| 温度保护 | 温度 ≥ 温度上限 → `Relay_OFF()` 断开继电器 | 代码已完成 |
| 断流保护 | 电流读数 = 0 → `Relay_OFF()` | 代码已完成 |
| 阈值调整 | 按键 K1 加 1 ℃、K2 减 1 ℃（最低 5 ℃） | 已完成 |
| 状态显示 | 8×8 点阵：√ 正常 / × 保护 | 已完成 |
| 上电初始化 | 点阵初始化 → INA219 初始化 → 继电器吸合 → 点阵显示 √ | 已完成 |

### 程序结构

程序没有用中断，也没有状态机，就是一个很直接的 `while(1)` 轮询主循环，
把"显示、按键、采集、保护判断"按顺序过一遍：

```c
void main()
{
    MatrixLED_Init();      /* 点阵 */
    INA219_Init();         /* 电流传感器 */
    Relay_ON();            /* 继电器吸合 */
    Matrix_Set(OK);        /* 点阵显示 √ */

    while(1)
    {
        Matrix_Refresh();              /* ① 点阵扫描，放最前面，负责显示 */

        KeyNum = Key();                /* ② 按键：K1 上限 +1，K2 上限 -1 */
        if(KeyNum == 1) TemperatureLimit++;
        if(KeyNum == 2 && TemperatureLimit > 5) TemperatureLimit--;

        Count++;                       /* ③ 计数，够 500 次才采集一次 */
        if(Count >= 500)
        {
            Count = 0;

            DS18B20_ConvertT();        /* 启动温度转换 */
            Delay(750);                /* 等转换完成 */
            Temperature = DS18B20_ReadT();

            Current = INA219_ReadCurrent();

            if(Temperature >= TemperatureLimit)   /* 温度保护 */
            {
                Relay_OFF();
                Matrix_Set(ERROR);
            }

            if(Current != 0)                      /* 电流判断 */
            {
                Relay_ON();
                Matrix_Set(OK);
            }
            else
            {
                Relay_OFF();
                Matrix_Set(ERROR);
            }
        }
    }
}
```

## 二、硬件与接线

| 模块 | 单片机引脚 | 说明 |
| --- | --- | --- |
| 继电器 IN | **P1.0** | 高电平吸合、低电平断开 |
| INA219 SDA | **P1.2** | 软件模拟 I2C |
| INA219 SCL | **P1.3** | 软件模拟 I2C |
| DS18B20 DQ | **P3.7** | 单总线 |
| 点阵 74HC595 SER | **P3.4** | 串行数据输入 |
| 点阵 74HC595 SCK | **P3.6** | 移位时钟 |
| 点阵 74HC595 RCK | **P3.5** | 锁存时钟 |
| 点阵列选 | **P0** | 直接驱动 8 列 |
| 按键 K1 / K2 | **P3.0 / P3.1** | 温度上限 +1 / −1 |
| 按键 K3 / K4 | **P3.2 / P3.3** | 本版本未使用 |

> INA219 必须**串在充电主回路里**（分流电阻串在电源和负载之间）才测得到电流，
> 只把 SDA / SCL 接到单片机是不会有电流读数的。

## 四、编译与烧录

### 编译

用 Keil uVision 打开 `project_1.uvproj`，直接 Build 即可。当前编译结果：

```
Program Size: data=31.2 xdata=0 code=1583
".\Objects\project_1" - 0 Error(s), 4 Warning(s).
```

4 条警告都是 `WARNING L16: UNCALLED SEGMENT`，意思是 `Timer0_Init()`、`Relay_Init()`、
`INA219_Check()`、`INA219_ReadBusVoltage()` 这几个函数定义了但没被调用，不影响运行。

> 代码大小 1583 字节，用 Keil 评估版（2048 字节代码上限）也能编译通过。

> **关于 `I2C.c`**：本工程原本只在 `I2C.h` 里声明了 `I2C_ReceiveByte()` 和
> `I2C_SendAck()`，却没有写实现，而 `INA219.c` 里调用了它们，链接时会报
> `UNRESOLVED EXTERNAL SYMBOL`。现已在 `I2C.c` 末尾补上这两个函数的实现
> （写法照搬工程里另一份 `I^2C.c`），其余代码未作改动。

### 烧录

直接用 `Objects/project_1.hex`，用 **STC-ISP** 烧到 STC89C52，
烧完拔插一次 USB（冷启动）程序才会开始跑。

## 六、实践过程与遇到的问题

这个作品做下来，最大的收获不是把功能全做通了，而是碰到了 **三个硬件问题**：

### 1. DS18B20 温度传感器引脚松动，读不到温度

DS18B20 装在面包板边上，三个引脚（VCC / DQ / GND）比较细，插进去以后是松的。
上电后时好时坏，稍微碰一下线温度就读不对了。单总线协议对时序很敏感，
接触不良的时候读回来的数据根本没法用。

**影响**：温度保护没法稳定工作。
**处理**：温度读取的代码留着没有删，先把重点放在电流这一路。

### 2. INA219 模块的接线端子是自己焊的，焊点不好，检测不到电流

INA219 模块上的接线端子是自己焊的，焊锡上得不好，有一路虚焊。
结果就是 I2C 通信时好时坏，读回来的电流值不对，甚至读不到设备。

**影响**：电流采集不可靠，断流保护也就无从谈起。
**处理**：一开始怀疑是软件问题，把 I2C 时序翻来覆去查了一遍，最后才意识到是焊点的问题。

### 3. LCD1602 引脚接触不良，后来干脆拿它当负载用了

最开始是打算用 **LCD1602 显示**充电状态的（所以工程里留下了 `LCD1602.c/h`），
但 LCD1602 的排针和面包板接触不良，屏幕经常是一排方块、或者干脆不显示，怎么调都不稳定。

**后来怎么处理的**：直接把 LCD1602 当成**负载**用了 —— 它的**背光一直是好的**，
通电背光就亮，正好可以直观地看出继电器到底有没有把回路接通。

**影响**：最终版本里显示改成了 8×8 点阵（`MatrixLED.c`），
LCD1602 的驱动代码留在工程里，但没有接进 Keil 工程编译。

## 七、已知问题 / 后续可做

**代码层面：**

* **两条保护判断会互相覆盖**：`Temperature >= TemperatureLimit` 那一段先执行，
  紧接着第二段 `if(Current != 0)` 又执行一次，会把前面温度保护的结论覆盖掉
  —— 比如温度超限断开继电器后，只要电流还不为 0，下一轮代码又会把继电器吸合回去。
  要修的话，应该把两段合成一条 `if / else if / else` 分支链，每轮只产生一个结论。
* **电流判断太粗糙**：现在只判"电流是不是 0"，还没有判"电流有没有超过上限"，
  也还没有"充满之后自动断电"的逻辑。原计划是电流降到阈值以下并持续一段时间就判定充满。

**硬件层面：**

* DS18B20：把引脚焊牢或者换个传感器，温度保护马上就能用起来。
* INA219：把端子重新焊一遍，电流读数稳定了，断流 / 过流保护才有意义。
* LCD1602：如果还想用 LCD 显示，把排针改成焊死的、或者换一根排线。

**功能上还没做的：**

* 充满自动断电（前提是先有稳定的电流读数）
* 过流保护阈值（同上）
* 充电时长计时显示
