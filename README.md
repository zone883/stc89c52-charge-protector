# 充电保护器 (Charge Protector)

> **Lithium-battery charging protector built on an 8051 MCU (STC89C52).**
> It measures the charging current & voltage with an **INA219**, cuts the relay on
> **over-current** or when the battery is **full**, and logs the charging time.
> Thresholds are adjustable with on-board keys; status is shown on an LCD1602 and
> the on-board LED bar. Written in Keil C51. Demo slides / operation manual are in
> [`docs/`](docs) (Chinese).

基于 51 单片机(STC89C52 / AT89C52)的锂电池充电保护装置。

通过 **INA219 检测充电电流与电压**，在过流、充满时自动切断继电器，并记录本次充电时长；
独立按键可调阈值，LCD1602（或板载点阵）显示。DS18B20 温度保护代码完整保留，
因传感器硬件故障（引脚松动接触不良）暂时关闭，见 `main.c` 的 `TEMP_SENSOR_EN` 宏。

## 一、功能

| 功能 | 实现方式 |
| --- | --- |
| 充满自动断电 | INA219 电流跌到阈值以下并持续 5 秒 → 判定充满 → 断开继电器（**必须本周期真的测到过充电电流**才允许判满） |
| 过流保护 | INA219 电流超过阈值持续 1 秒 → 跳闸断电，**自锁**，需按 K4 复位（像空气开关） |
| 温度保护(保留) | DS18B20 超温断电、2℃ 回差自动恢复；传感器硬件故障暂关，`TEMP_SENSOR_EN` 改 1 即恢复 |
| 可设阈值 | 独立按键 K1/K2 调整「充满判定电流 FULL，默认 20mA」或「过流保护电流 OVER，默认 100mA」，K3 长按切换要调的参数；原则是 **FULL < 实际充电电流 < OVER** |
| 已充电时间 | 定时器 1ms 心跳计时，LCD1602 以 `时:分:秒` 显示 |
| 状态提示 | LCD 显示 `CHRG / FULL / HOT! / OC!! / IDLE`；点阵用 √ / × / 闪烁感叹号表示 |
| 故障自检 | 开机检测 DS18B20 与 INA219，屏幕直接显示 `T-SENS:OK/FAULT/OFF`、`INA:OK/NG`、`RLY:ON/OFF` |
| 状态指示(板载LED) | 用板载 8 个 LED：充电中按电流亮 1~8 格柱状条（以 OVER 阈值为满格），充满全亮，保护动作时整排闪烁；开机跑流水灯验灯 |
| 开机硬件体检 | 不用屏幕也能看懂：**LED 亮 4 格停一下 = INA219 在线**、**整排闪 3 次 = 不在线**。点阵同时给结论：√ 正常、! 闪 = INA219 有问题、× 闪 = 正在保护 |
| 按键反馈 | 按住任意键 → 板载 LED 亮对应格数（K1=1 格 … K4=4 格），松手后保持 1 秒；长按被识别时该条闪烁。**没有显示屏也能确认每个键都生效**，顺便可以验证按键丝印与引脚的对应关系 |
| 防误判设计 | 只有"本周期真的测到过 ≥FULL 阈值的充电电流"之后才允许判满。若负载没串进测量回路（电流读数恒 0），程序不会一上电就误当"充满"断电 |
| 优雅降级 | 传感器掉了不会乱动作：温度无效就只做电流保护，电流无效就只做温度保护；掉线后每 2 秒自动重试初始化 |

### 断电/恢复逻辑（状态机）

```
        ┌──────────── 温度 >= 上限 ────────────┐
        │                                      ▼
   ┌─────────┐   有负载且电流正常        ┌────────────┐
   │  IDLE   │ ───────────────────────▶ │  CHARGING  │
   │ (空载)  │ ◀─────────────────────── │  (充电中)  │
   └─────────┘   电压 < 3V(拔掉负载)     └────────────┘
        ▲                                 │        ▲
        │              电流 < 阈值且持续 5s │        │ 温度降回 (上限-2)℃
        │                                 ▼        │
        │                            ┌────────┐    │
        └────────────────────────────│  FULL  │    │
                                     │ (已充满)│   │
                                     └────────┘    │
                                     ┌────────────────┐
                                     │   OVERHEAT     │
                                     │ (过温保护断开) │
                                     └────────────────┘
                              ┌──────────────────────┐
                              │      OCURRENT        │
                              │ (过流跳闸, 自锁:     │
                              │  电流 > 上限持续 1s, │
                              │  需按 K4 手动复位)   │
                              └──────────────────────┘
```

关键点：**所有判断合成一条 if / else 分支链，每个控制周期只产生一个结论**，
不会出现「温度保护刚断开继电器，下一句又把继电器吸合」这种互相打架的情况。

## 二、硬件与接线

| 模块 | 引脚 | 说明 |
| --- | --- | --- |
| 5V 单路继电器模块(带光耦隔离) | P1.0 | **低电平触发**，见 `Relay.c` 顶部宏 |
| INA219 SDA / SCL | P1.2 / P1.3 | 见 `I2C.c` 顶部两行 |
| DS18B20 DQ | P3.7 | 见 `OneWire.c` 顶部 |
| 独立按键 K1~K4 | **P3.1 / P3.0 / P3.2 / P3.3**（注意不是顺序的） | 按下为低电平；映射表在 `Key.c` 顶部，一行可改 |
| 状态指示(板载 8 个 LED) | P2.0 ~ P2.7 | 共阳接法低电平点亮；充电中按电流亮柱状条 |
| LCD1602 | RS=P2.6 RW=P2.5 EN=P2.7 D0~D7=P0 | |
| 点阵(74HC595) | SER=P3.4 RCK=P3.5 SCK=P3.6 列=P0 | |

> **几个注意点**
> 1. **LCD1602 与点阵共用 P0**，实际只能接一块。程序开机自动识别：读到 LCD 应答就用
>    LCD，否则自动切到点阵显示状态图标，不至于"什么反应都没有"。
> 2. 继电器模块的触发极性（高/低）只需改 `Relay.c` 里的 `RELAY_ACTIVE_LOW`。
>    开机自检会"咔哒"两下，若动作方向相反把它取反即可。
> 3. **板载 LED 与 LCD 显示互斥**：8 个 LED 占用 P2.0~P2.7，其中 P2.5/2.6/2.7 同时是 LCD 的
>    RW/RS/EN。本作品把 LCD 当负载用（不接数据线），所以不冲突；若要两者共存，把
>    `LED.h` 里 `LED_BAR_N` 从 8 改成 5（只用 P2.0~P2.4）。
>    另外 P2.5 在许多板子上接了蜂鸣器（亮到第 6 格可能响，可拔跳线帽），
>    P2.2/2.3/2.4 兼作数码管位选（亮这几格时数码管可能轻微窜光，属正常）。
> 4. **仍然空闲的引脚**：`P1.1`、`P1.4`、`P1.5`、`P1.6`、`P1.7` 以及 `P3.7`（DS18B20 停用后空出），
>    要加外接 LED、蜂鸣器、额外按键都挂这里。

### 负载回路（INA219 必须串进主回路才测得到电流）

```
开发板 5V  ──▶  继电器 COM
继电器 NO  ──▶  INA219 VIN+
INA219 VIN- ──▶  负载正极
负载负极   ──▶  开发板 GND
INA219: VCC→5V  GND→GND  SDA→P1.2  SCL→P1.3  (A0/A1 悬空 = 地址 0x40)
```

负载选一种即可：

* **LCD1602 当负载**（本作品实际采用）：只接 VDD/VSS 供电、数据线不接。
  它既是耗电负载又是"电源指示灯"——跳闸瞬间屏幕熄灭，非常直观；显示由板载点阵完成。
* **LED + 100Ω 当负载**：LCD1602 恢复当显示器（数据线、控制线照常接），
  开机程序自动识别，实时页显示电压/电流数字。

## 四、按键操作

| 按键 | 功能 |
| --- | --- |
| K1 短按 | 当前选中阈值 **+1 档** |
| K2 短按 | 当前选中阈值 **−1 档** |
| K3 短按 | 翻页（实时 → 阈值 → 自检） |
| K3 长按 | 切换要调的参数（充满电流 FULL / 过流保护 OVER） |
| K4 短按 | 复位（清充电计时、解除跳闸） |

**LCD 三个页面**

```
第 1 页(实时)      U:5.00V I:  25mA      第 2 页(阈值)   >FULL  20mA
                   CHRG 00:00:12                          OVER  100mA

第 3 页(自检)      T-SENS:OFF
                   INA:OK  RLY:ON
```

阈值页里 `>` 号标出当前正在调的是哪一个（`FULL` = 充满判定，`OVER` = 过流保护）。

**按键反馈条**：按住任意键，板载 LED 立刻亮对应格数（K1=1 格、K2=2 格、K3=3 格、K4=4 格），
松手后再保持 1 秒；长按被识别时这根条会闪。
因为本作品 LCD1602 是当负载用的（没有屏幕显示数字），这是"按键到底有没有生效"最直接的证据，
也能用来核对按键丝印与引脚的对应关系（按住丝印 K1，若亮 1 格说明映射正确）。

## 五、演示流程

1. **上电自检**：继电器"咔哒"两下 → 板载 LED 跑一遍流水灯再全亮一下 →
   **亮 4 格停一下 = INA219 在线** / **整排闪 3 次 = 不在线**。
   LCD 模式下先显示开机画面，再显示自检页（`T-SENS:OFF` / `INA:xx RLY:xx`），约 2.5 秒后回实时页。
2. **按键自检**：按住 K1~K4 各一下，LED 分别亮 1、2、3、4 格 —— 四个键全部生效。
3. **实时页**：`U:x.xxV I:  xxmA / CHRG 00:00:xx`，LED 柱状条随电流变化、计时在走 = 正在充电。
4. **过流保护演示（核心）**：把 OVER 阈值调到负载电流以下（按 K3 长按切到 OVER，K2 减到 20mA）→
   1 秒后继电器"咔哒"跳闸、负载断电（LCD 当负载时屏幕直接熄灭）、8 个 LED 整排交替闪烁、
   状态 `OC!!`；**按 K4 复位**恢复供电（记得把 OVER 调回去）。
   讲解点：*跳闸自锁，必须手动复位，像空气开关。*
5. **充满断电演示**：断开负载再接上，或让电流降到 FULL 阈值以下 → 5 秒后状态变 `FULL`、
   继电器断开、**LED 全亮**、计时停在断电瞬间。
   讲解点：*用"电流小于阈值并持续 5 秒"判满，而不是等电流等于 0；而且必须先真的测到过充电电流。*
6. **温度保护**：逻辑已完整实现（超温断电 + 2℃ 回差恢复），因传感器硬件故障暂用
   `TEMP_SENSOR_EN = 0` 关闭；换上好的 DS18B20 改一个宏即可用真实温度跑。

## 六、设计思路与调试记录

### 6.1 为什么这样写

* **采样不阻塞**：DS18B20 一次转换要 750ms。程序把它拆成「上一秒启动转换、下一秒取结果」，
  主循环始终是几十微秒一轮，按键、显示都不卡。
* **传感器容错**：每个控制周期都检查数据是否有效（存在脉冲、量程、寄存器回读），
  无效就降级到只保留可用的那一路保护，绝不拿垃圾数据去驱动继电器。
* **判满不能只看 0**：实际充电末期电流是逐渐衰减到几十 mA 的，用 `== 0` 永远等不到，
  所以改成「电流 < 阈值且持续 5 秒」。
* **默认阈值必须匹配负载**：FULL 阈值若高于实际充电电流，一上电 5 秒就被判"充满"；
  OVER 阈值若低于实际充电电流，一上电就跳闸。所以默认取
  `FULL = 20mA`、`OVER = 100mA`（LCD1602 负载约 25mA），并把准则写进代码注释：
  **FULL < 实际电流 < OVER**。
* **没测到电流就不许判满**：如果负载没串进测量回路（或模块虚焊），电流读数会恒为 0，
  原来的逻辑会立刻判"充满"断电，让人以为板子坏了。现在加了一个"本次充电是否真的测到过
  充电电流"的标志，没测到就永不判满 —— 现象会如实变成"一直充电中、柱子 1 格不动"，
  一眼就知道是**没测到电流**，而不是"充好了"。
* **回差防抖**：温度保护恢复要等降回 (上限-2)℃，否则继电器会在阈值附近疯狂开合。
* **硬件不可靠时的降级思路**：这套作品的短板全在硬件接触上（见 6.2）。
  所以程序里到处是"自检 + 如实上报 + 降级"：开机探测每一颗器件并把结果放到屏幕和 LED 上，
  坏了就明说（`T-SENS:OFF`、`INA:NG`、点阵 `!` 闪烁），而不是带着错误数据继续跑。

### 6.2 踩过的坑（实际问题 + 定位过程）

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 继电器 LED 亮但不吸合 | 模块是低电平触发，代码当成高电平写 | 逻辑取反，并把极性做成宏 `RELAY_ACTIVE_LOW` 方便切换 |
| **INA219 一直检测不到设备** | 模块的绿色接线端子是自己焊的，**焊点不良**，I2C 和测量回路时通时断 | 重焊加固；代码里加开机探测 + 掉线后每 2 秒自动重试初始化，自检页如实显示 `INA:NG` |
| **DS18B20 温度传感器无法检测温度** | 传感器引脚松动，插不紧、接触不良 | `TEMP_SENSOR_EN` 开关关闭真实测温、**代码全部保留**；页面 2 如实显示 `T-SENS:OFF`，其余保护不受影响 |
| **LCD1602 显示不稳定 / 时亮时不亮** | LCD 引脚接触不良，排线一碰就掉 | `LCD_Check()` 开机探测，屏幕不在就自动改用点阵显示状态图标，系统不会因此瘫痪 |
| I2C 读不到数据 / 链接报 `UNRESOLVED EXTERNAL I2C_RECEIVEBYTE` | `I2C.c` 里漏了 `I2C_ReceiveByte()`、`I2C_SendAck()` 两个函数，Keil 仍生成了 hex，运行时跳到无效地址 | 补全驱动，并在每次重新编译后确认 0 Error。**教训：编译日志里的 warning 不能不管** |
| 全程序 5660 字节，链接报 `L107 ADDRESS SPACE OVERFLOW` | 8051 只有 128 字节可直接寻址 RAM，且**未被调用的库函数不参与覆盖分析**，局部变量白占 RAM；另外大量 32 位运算还会额外引入库代码 | 删掉未使用的函数（LCD_ShowNum 等），计时器从 32 位改为 16 位，显示只留一个 17 字节行缓冲，最终 `data=116 / code=4577`（栈仍有约 130 字节） |
| 按 K1~K3 好像"没反应"，只有 K4 有变化 | 本作品 LCD1602 当负载用、没有屏幕显示数字，而 K1/K2 调阈值、K3 翻页的效果都只体现在屏幕数字上，所以看起来只有 K4 有效。**实际是 4 个键都生效，只是没有可见反馈** | 增加"按键反馈条"：任何键被按住时板载 LED 亮对应格数，松手保持 1 秒，长按闪烁；4 个键立刻全部可见 |
| 板上丝印 K1 和 K2 与代码对不上 | 普中/江协板 4 个独立按键的接法是 `K1=P3.1 K2=P3.0 K3=P3.2 K4=P3.3`，**不是** P3.0~P3.3 顺序 | `Key.c` 顶部 `KEY_PIN_MAP[4] = {1,0,2,3}` 按丝印顺序填引脚号；用按键反馈条按住 K1，亮 1 格即映射正确 |
| 程序一上电就"充满断电"，什么现象都没有 | ① 默认 FULL/OVER 阈值（50/60mA）与实际负载电流（约 25mA）不匹配，一上电就判充满；② 电流读数恒 0（负载没串进测量回路）时又被判成"充满"，状态永远停在 FULL | ① 默认值改成 `FULL=20 / OVER=100`，并把"FULL < 电流 < OVER"写进注释；② 加"必须测到过充电电流才许判满" |
